## Дизайн Portable: четыре раздела и избранное (9 ноября 2026)

Актуальные исходники Portable получили тёмное окно с клиентской областью
390 × 760 логических пикселей, четырьмя плитками «Детали», «Чертежи»,
«Сборки», «Лазер», списками макросов разделов и избранным на главной.
Поиск на главной работает по всей библиотеке, внутри раздела — по нему.
Звёздочки сохраняются в portable.json; старые настройки читаются без Favorites.
Диалог процедур оформлен в той же тёмной палитре. Техническая цепочка
GetMacroMethods / RunMacro2 и блокировка повторного запуска сохранены.

Выбранная библиотека получает четыре одноимённые папки. Сканируются корень
и непосредственно эти папки; глубже — нет. Корневые известные чертёжные
макросы доступны в «Чертежи», остальные — в «Без раздела». Файлы пользователя
автоматически не перемещаются. Рабочих .swp в этом окружении нет; разложить
их физически не удалось. Два известных макроса следует положить в «Чертежи».
Полный путь остаётся ключом настроек: после ручного перемещения файла
процедуру и избранное нужно выбрать заново.

Сборка с .NET SDK 8.0.427 и interop NuGet 32.1.0 (API 2024): без ошибок
и предупреждений. Сканер и разбор процедур: 24 проверки. Включены одинаковые
имена в разных разделах, старые корневые файлы, отсутствие рекурсии,
категории и повторное создание папок. ZIP пересобран с пустыми папками
разделов и обновлённым SHA-256. Windows/WinForms, DPI и реальные COM/VBA
после изменения интерфейса в облаке не запускались; требуется приёмка.
Пользователь разрешил публикацию этих изменений в GitHub 9 ноября 2026.


WinForms net48 x64, asInvoker, без регистрации COM/дополнения и WebView2.
`Marshal.GetActiveObject("SldWorks.Application")` подключается к открытому SolidWorks; `RunMacro2` выполняется синхронно из главного STA-потока приложения, COM маршалит вызов в процесс SolidWorks. Не используются фоновые потоки, SendKeys или имитация мыши. Несколько экземпляров SW не выбираются автоматически — оставить один.

Каталог и проверка пути переиспользуются из ../Catalog.cs. При каждом запуске перечитывается запись по id, проверяются файл и тип документа. Папка приложения должна быть доступна для записи пользователю. Пока выполняется макрос, кнопка запуска и закрытие заблокированы. Приложение не запускает и не закрывает SolidWorks.

Сборка разработчиком:

```
dotnet build addin/portable/SWToolsHub.Portable.csproj -c Release -p:SolidWorksInteropPath="C:\Program Files\SOLIDWORKS Corp\SOLIDWORKS\api\redist"
python installer/build-portable.py
```

Для проверки в Linux использованы справочные interop NuGet 32.1.0 (2024). Windows запуск, подключение/отсутствие SolidWorks, неверный документ, отсутствие файла, оба реальных макроса, закрытие SW и повторное подключение ещё требуют проверки. Существующие React и Task Pane не удалены. Текущая native-версия содержит список, поиск и запуск; избранное/темы React в ней пока не перенесены.

## Динамическая папка

Список Portable теперь строится по .swp верхнего уровня выбранной папки, без зависимости от Library/macros.json. Имя — фактическое имя файла. WinForms Timer раз в 2 секунды обновляет список на UI-потоке, пропуская обновление во время запуска; пустая/недоступная папка не оставляет старые записи. Настройки папки и процедур хранятся в LocalAppData/SWToolsHub/portable.json. Папка не изменяется.

Для известных префиксов «Авторазмер»/«Свердловка» сохранены точки входа и требование чертежа. Для остальных вызывается GetMacroMethods, пользователь выбирает точку входа или вводит её вручную; требуется открытый документ. Это не проверяет пригодность документа для стороннего VBA. Выбор процедуры можно изменить отдельной кнопкой.

Проверки сканера: `dotnet run --project addin/tests/folder/Folder.Checks.csproj` (8 проверок, без запуска VBA). Компиляция portable проходит; GetMacroMethods и интерфейс выбора папки ещё требуют проверки Windows. Пользователь подтвердил запуск первого макроса в предыдущей версии, второй не запускался из-за несовпадения ожидаемого имени/расположения файла.

## Выбор модуля и процедуры

Диалог точки входа заменён на TableLayoutPanel с DPI-масштабированием, отдельными ComboBox «Модуль»/«Процедура» и кнопкой повторного запроса GetMacroMethods. Обработчик принимает System.Array (в том числе SAFEARRAY с ненулевой нижней границей), строку, пустой ответ, устраняет дубликаты. Ошибки/пустой ответ отображаются явно. Для известных имён подставляется прежняя точка входа; добавлены алиасы «Сверловка» и «Weldment Drilling». Сохранённая процедура доступна для изменения; ручной ввод остаётся при отсутствии результатов API. Для сверловки известная точка — InsertWeldWithHoles.start.

Сборка net48 прошла без ошибок/предупреждений; 15 проверок сканера и обработки процедур прошли. Реальный ответ GetMacroMethods и новый диалог ещё требуют проверки на Windows. Пустой ответ API не означает, что VBA-проект не содержит других модулей: приложение не разбирает бинарный VBA-проект.

## Выбор папки и кнопки

В Portable заменён старый FolderBrowserDialog: теперь используется системный Common Item Dialog Windows (IFileDialog в режиме выбора папки), с адресной строкой, навигацией и начальной выбранной папкой. Диалог модален к окну приложения, не запускает отдельный Explorer. Никаких сторонних компонентов или регистрации. Отмена не меняет сохранённую папку.

Дублирующие нижние кнопки удалены. Остались «Выбрать процедуру и запустить…» и перенесённая вниз «Выбрать папку макросов…». Сборка и 15 проверок логики прошли. Системный диалог/компоновка требуют проверки на Windows: в Linux их не запускали.
