# Сборка и установка на Windows

Подготовлены исходники дополнения и скрипты установки. Запуск внутри SolidWorks 2025 ещё требует проверки на Windows: облачная Linux-среда не может подтвердить работу COM, Task Pane, WebView2 и VBA.

## Быстрый запуск из ZIP репозитория

Установите Node.js 22.12+ и .NET SDK 8+, закройте SolidWorks и запустите `Установить.cmd` двойным щелчком. Скрипт `Setup.ps1` соберёт пакет с interop установленного SolidWorks (при нестандартном пути предложит выбрать папку), затем запросит UAC и выполнит установку. Ошибки остаются в консоли. После установки откроется папка для двух рабочих .swp; скопируйте их отдельно. Скрипт не скачивает и не публикует макросы. Для сборки требуется Интернет к npm/NuGet.

## Сборка пакета разработчиком

Нужны Windows x64, SolidWorks 2025, .NET SDK 8 или новее, .NET Framework 4.8 Developer Pack, Node.js 22.12+ и npm. Interop-сборки берутся из установленного SolidWorks (`api\redist`); не скачивайте их из случайных источников. Для восстановления NuGet и npm нужен Интернет.

В PowerShell из корня репозитория:

```powershell
.\addin\scripts\Build-Package.ps1
# Если SolidWorks установлен иначе:
.\addin\scripts\Build-Package.ps1 -SolidWorksInteropPath 'D:\SOLIDWORKS\api\redist' -OutputPath 'D:\Packages\SWToolsHub-01'
```

Скрипт выполняет `npm ci`, production-сборку UI, `dotnet build` Release/x64 и собирает каталог `artifacts\SWToolsHub`. Если каталог результата уже существует, укажите новый путь: рабочие файлы не удаляются автоматически. Перед передачей инженеру выполните браузерные тесты (`cd frontend; npx playwright install chromium; npm test`). Рабочие `.swp` не включаются в пакет. Пакет содержит DLL дополнения, WebView2 SDK и loader, локальный `ui`, каталог `Library\macros.json` и скрипты.

Передайте инженеру **весь каталог пакета**, например ZIP-архивом. Отдельная DLL недостаточна. Node.js и SDK на компьютере инженера не нужны.

## Установка инженером

1. Установите Windows x64, SolidWorks 2025, .NET Framework 4.8 и Microsoft Edge WebView2 Evergreen Runtime x64 с официального сайта Microsoft: https://developer.microsoft.com/microsoft-edge/webview2/ . Runtime нужен даже при локальной загрузке UI.
2. Распакуйте пакет в отдельный каталог. Закройте SolidWorks. Откройте **64-разрядный Windows PowerShell от имени администратора** под своей учётной записью. Из распакованного пакета выполните `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1`. Bypass действует только для этого процесса; сначала ознакомьтесь со скриптом. Политики организации могут запрещать запуск: в таком случае используйте утверждённую администратором процедуру.
3. По умолчанию файлы копируются в `C:\Program Files\SWToolsHub`, выполняется COM-регистрация через 64-разрядный .NET RegAsm `/codebase`, создаются ключи SolidWorks. Другой путь: `-InstallPath 'D:\Apps\SWToolsHub'`. Не перемещайте установленный каталог без повторной регистрации. При обновлении существующий `Library\macros.json` сохраняется; согласуйте его изменения вручную.
4. Передайте рабочие макросы на Windows отдельно и скопируйте **без изменения содержимого**:

   ```text
   C:\Program Files\SWToolsHub\Library\Macros\Авторазмер Рамы.swp
   C:\Program Files\SWToolsHub\Library\Macros\Свердловка.swp
   ```

   Потребуются права администратора для записи в Program Files. Файлы уже получены пользователем на исходном Mac в игнорируемой папке `local-macros/`. Второй оригинал «Свердловка (2).swp» переименован в «Свердловка.swp», SHA-256 копий совпал с оригиналами. Пользователь также передал оба файла вложениями в облако; копии сохранены в исключённой из Git папке local-macros/, SHA-256 каждой копии совпадает с вложением. На Windows их необходимо перенести отдельно.
5. Запустите SolidWorks. В «Сервис → Дополнения» включите **SW Tools Hub** и при необходимости автозагрузку. HKCU автозагрузки создаётся для учётной записи административного PowerShell; при установке от другой учётной записи включите автозагрузку вручную у инженера.
6. Откройте подходящий чертёж с моделью и видами. В Task Pane выберите инструмент и нажмите «Запустить». AutoSize вызывает `FrameCutListDimensionsV3.main`, Weldment Drilling — `InsertWeldWithHoles.start`. Общая проверка типа «чертёж» не доказывает пригодность содержимого чертежа для конкретного VBA: выбирайте подходящую модель и сначала работайте с копией.

## Каталог и диагностика

Авторитетный каталог выполнения — `Library\macros.json` рядом с установленной DLL; UI передаёт только id, а не путь или процедуру. Файлы лежат в `Library\Macros`. Не редактируйте каталог во время запуска макроса. Сетевая папка в настройках UI пока не используется для выполнения.

Если дополнение отсутствует в списке, проверьте успешный код RegAsm, x64-процесс регистрации, наличие всех зависимостей пакета и ключ `HKLM\SOFTWARE\SolidWorks\Addins\{13B0B588-6E90-46B3-B76A-13DC794957A6}`. Если панель не загрузилась, проверьте WebView2 Runtime, `ui\index.html`, права на пользовательский профиль WebView2 и сообщение дополнения. При ошибке запуска проверьте тип активного документа, имя `.swp`, модуль и процедуру в JSON, настройки доверия к VBA в SolidWorks. Не отключайте защиту макросов глобально; следуйте правилам организации.

## Выгрузка и удаление

Выключение дополнения в «Сервис → Дополнения» освобождает Task Pane/WebView2. Для удаления закройте SolidWorks и запустите **из установленного каталога** в административном x64 PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Uninstall.ps1
```

Скрипт отменяет COM-регистрацию и удаляет ключи дополнения/автозагрузки текущего пользователя. Файлы приложения, рабочие макросы и профиль WebView2 сохраняются. После резервного копирования `Library` можно вручную удалить каталог установки. У других Windows-пользователей при необходимости удалите оставшийся ключ `HKCU\Software\SolidWorks\AddInsStartup\{13B0B588-6E90-46B3-B76A-13DC794957A6}` в их профилях.

## Обязательная приёмка на Windows

Пока не выполнена. Проверить: сборку с настоящими interop SolidWorks 2025; установку на чистой машине без Node; панель и локальные ресурсы без dev-сервера; оба реальных макроса на подходящих чертежах; отсутствие документа, деталь/сборку, отсутствующий `.swp`, неверный id/модуль/процедуру, ошибки VBA; повторные клики и повторный вход при исполнении; закрытие/смену документа; выключение и повторное включение дополнения; перезапуск SolidWorks с автозагрузкой; удаление и сохранность библиотеки. Зафиксировать версии, результаты и реальные ошибки. Сообщение об успешном вызове RunMacro2 не заменяет проверку результата VBA на чертеже.
