# Продолжение разработки SW Tools Hub

Актуализировано 7 ноября 2026. Читать вместе с AGENTS.md, README.md, docs/ARCHITECTURE.md и docs/INSTALL.md.

## Фактическое состояние

Этап 1 сохранён: React + TypeScript + Vite, поиск, категории, избранное, темы, настройки, 320 px и браузерный деморежим. Прежний интерфейс не заменён.

Добавлены исходники этапа 2: C# COM Add-in .NET Framework 4.8 x64 с ISwAddin, Task Pane и WebView2. UI загружается из локального каталога ui через виртуальный HTTPS origin WebView2, без сервера и Node.js у инженера. C# читает Library/macros.json и принимает от интерфейса только команду и id, самостоятельно выбирает файл, модуль и процедуру. Проверяет локальное имя .swp, наличие файла и открытый документ типа «чертёж», блокирует повторный запуск и вызывает RunMacro2 в потоке SolidWorks. Результат возвращается в интерфейс. Геометрию и пригодность конкретного чертежа должен проверить инженер: проверка типа документа не гарантирует пригодность модели для VBA.

Исходники дополнения и сценарии сборки/установки находятся в addin/. Краткая инструкция для Windows — УСТАНОВКА.txt, подробная — docs/INSTALL.md. Сборка пакета выполняется разработчиком на Windows с interop-сборками установленного SolidWorks 2025. Пакет не содержит рабочих макросов.

## Рабочие макросы: уточнение пользователя

Оба оригинальных .swp уже получены пользователем и первоначально сохранены **на исходном Mac** в исключённой из Git папке local-macros/. Второй оригинал назывался «Свердловка (2).swp», копия переименована в «Свердловка.swp» без изменения содержимого. По сообщению пользователя SHA-256 копий совпал с оригиналами. В этой сессии пользователь дополнительно передал оба .swp вложениями. Они скопированы в облачную исключённую из Git папку local-macros/ под именами «Авторазмер Рамы.swp» и «Свердловка.swp». SHA-256 каждой облачной копии совпадает с соответствующим вложением; сравнение с оригиналами на Mac повторно не выполнялось. VBA не изменялся и не запускался. Фиктивные макросы не создавались.

## Проверки облака

- Установлены npm-зависимости по package-lock.json.
- TypeScript и production-сборка Vite проходят.
- Все 6 прежних браузерных сценариев проходят в системном Chromium.
- Добавлен и проходит браузерный тест моста с имитацией WebView2: каталог от хоста, передача только id, блокировка кнопки и показ ошибки отсутствующего файла. Этот тест не запускает COM или VBA.
- Сборка C# прошла без ошибок и предупреждений. Она проверена в Linux с .NET SDK и reference assemblies .NET Framework. Для проверки API используются подлинные interop NuGet SolidWorks 2024 (32.1.0), не замена обязательной Windows-сборки с interop 2025.

- 11 переносимых проверок валидатора JSON прошли: схема, дубликаты id, обход каталогов, расширение, тип документа, повреждённый/отсутствующий каталог. Используется реальный Catalog.cs с адаптером сериализации System.Text.Json; .NET Framework JavaScriptSerializer этим тестом не проверяется. Запуск: `dotnet run --project addin/tests/Catalog.Checks.csproj -- config/macros.demo.json` из корня (SDK 8+).
- Синтаксис всех трёх PowerShell-сценариев проверен AST-парсером PowerShell 7.4.6: ошибок нет. Операции Windows/реестр этим не проверяются.

## Границы проверки и обязательная приёмка

Windows, SolidWorks 2025 и тестовые CAD-документы в облаке недоступны. Реальные .swp теперь доступны локально в local-macros/, но выполнить их в этой Linux-среде нельзя. COM-регистрация, WebView2 внутри Task Pane, загрузка/выгрузка в SolidWorks и оба реальных вызова VBA здесь **не проверены**. Компиляция и браузерные тесты не подтверждают эти сценарии.

На Windows: собрать пакет с interop 2025; установить WebView2 Runtime; закрыть SolidWorks; выполнить Install.ps1 от администратора; передать оригинальные .swp в Library/Macros; включить дополнение. Проверить оба макроса на копиях подходящих чертежей, отсутствие документа, деталь/сборку вместо чертежа, отсутствующий файл, неверную точку входа, повторный запуск и отключение/повторное включение дополнения. Полный список в docs/INSTALL.md. У инженера Node.js не требуется.

## Portable без администратора (9 ноября 2026)

По просьбе пользователя добавлено отдельное WinForms-приложение addin/portable, net48 x64, manifest asInvoker. Оно подключается к открытому SolidWorks через GetActiveObject и выполняет RunMacro2 из главного STA потока (COM маршалит вызов в SW). Установки и регистрации дополнения, WebView2/Node/SDK на машине пользователя нет. Требуется системный Framework 4.8. Список, поиск и запуск реализованы; React-интерфейс сохранён отдельно, его темы/избранное в native UI не перенесены.

Публичный installer/SWToolsHub-Portable.zip содержит EXE, interop DLL, конфигурацию и русскую инструкцию; .swp исключены. Сборка portable прошла с 0 ошибок/предупреждений на interop API2024. Упаковщик проверяет CRC архива, отсутствие .swp и WebView2. Приёмка Windows, GetActiveObject, COM и VBA ещё не выполнена. Не утверждать работу в SolidWorks до реального теста. Старая административная установка остаётся альтернативой, не используется в Portable.

## Динамический список Portable

Пользователь подтвердил реальный запуск первого макроса на Windows в предыдущей Portable-версии. Второй выдавал отсутствие файла. Теперь Portable сканирует выбранную папку .swp (только верхний уровень), показывает имена файлов, обновляет список раз в 2 секунды, запоминает корневую папку в LocalAppData. Известные префиксы сопоставляются с прежними процедурами, для новых — GetMacroMethods и выбор/ручной ввод процедуры, сохраняемый по пути. Доступна смена точки входа. Проверены 8 сценариев сканера и компиляция; новое UI/персистентность/GetMacroMethods/второй макрос ещё не проверены в Windows.

## Выбор модуля и процедуры

Диалог точки входа заменён на TableLayoutPanel с DPI-масштабированием, отдельными ComboBox «Модуль»/«Процедура» и кнопкой повторного запроса GetMacroMethods. Обработчик принимает System.Array (в том числе SAFEARRAY с ненулевой нижней границей), строку, пустой ответ, устраняет дубликаты. Ошибки/пустой ответ отображаются явно. Для известных имён подставляется прежняя точка входа; добавлены алиасы «Сверловка» и «Weldment Drilling». Сохранённая процедура доступна для изменения; ручной ввод остаётся при отсутствии результатов API. Для сверловки известная точка — InsertWeldWithHoles.start.

Сборка net48 прошла без ошибок/предупреждений; 15 проверок сканера и обработки процедур прошли. Реальный ответ GetMacroMethods и новый диалог ещё требуют проверки на Windows. Пустой ответ API не означает, что VBA-проект не содержит других модулей: приложение не разбирает бинарный VBA-проект.
