# SW Tools Hub — контекст для Codex

Этот README предназначен для продолжения разработки в новом чате без предыдущей переписки. Актуализировано 9 ноября 2026.

## С чего начать

1. Прочитай [AGENTS.md](AGENTS.md), этот README и [docs/HANDOFF.md](docs/HANDOFF.md).
2. Проверь `git status`, текущие исходники и последние коммиты. Сохрани существующие изменения пользователя.
3. Для актуального приложения изучи `addin/portable/`, его [README](addin/portable/README.md), тесты `addin/tests/folder/` и упаковщик `installer/build-portable.py`.
4. Сверяй исторические записи с текущим кодом: упоминания «этап 1», будущего Add-in и React как единственного UI в старых документах устарели. Текущий приоритет пользователя — **Portable без прав администратора и установки дополнений**.

## Что разрабатываем сейчас

SW Tools Hub Portable — отдельное Windows-приложение C#, .NET Framework 4.8, x64, Windows Forms, manifest `asInvoker`. Подключается к уже открытому SolidWorks через `Marshal.GetActiveObject("SldWorks.Application")`, вызывает официальный API `GetMacroMethods` и `RunMacro2`. COM-вызовы идут из главного STA-потока приложения с маршалингом в процесс SolidWorks, без фоновых потоков, SendKeys и имитации мыши.

У пользователя нет прав администратора. Не возвращай основной сценарий к установщику, COM-регистрации, Task Pane или WebView2. Node.js и .NET SDK допустимы на машине сборки, но не должны требоваться пользователю. Системный .NET Framework 4.8 остаётся runtime-требованием.

## Карта актуального кода

- `addin/portable/Program.cs` — главное окно, сохранение настроек, подключение к SW, проверки документа/файла, блокировка повторного запуска и выполнение VBA.
- `MacroFolder.cs` — реальные `.swp` верхнего уровня выбранной папки. Имя элемента берётся из имени файла, пустая папка даёт пустой список. Обновление раз в две секунды, без сканирования вложенных папок.
- `FolderPicker.cs` — системный Windows Common Item Dialog с адресной строкой, модальный к приложению; не старый FolderBrowserDialog.
- `EntryDialog.cs` — выпадающие списки модуля и процедуры, повторная загрузка из SW, ручной ввод при отсутствии ответа API.
- `MacroEntry.cs` — обработка возвращаемых COM-массивов/строк, разбор и устранение дубликатов процедур.
- `%LOCALAPPDATA%\SWToolsHub\portable.json` — выбранная папка и точки входа по полному пути файла. Это пользовательские настройки, не файл репозитория.
- `installer/build-portable.py` — упаковка готовых EXE/interop DLL/конфигурации/инструкции в `installer/SWToolsHub-Portable.zip`, обновление `PORTABLE-SHA256.txt`. Рабочие `.swp` не включаются.

В последнем UI оставлены две кнопки: «Выбрать процедуру и запустить…» и ниже «Выбрать папку макросов…». Дублирующие кнопки убраны по просьбе пользователя. Современный дизайн обсуждался, но не реализован: сначала стабилизировать запуск и выбор процедур, затем менять оформление.

## Макросы и безопасность

| Макрос | Исходное имя файла | Модуль | Процедура |
| --- | --- | --- | --- |
| AutoSize | Авторазмер Рамы.swp | FrameCutListDimensionsV3 | main |
| Сверловка / Weldment Drilling | Свердловка.swp | InsertWeldWithHoles | start |

Для этих известных макросов проверяется тип документа «чертёж». Конкретную пригодность модели/видов это не доказывает. Для других макросов требуется открытый документ; пользователь выбирает процедуру из API или вводит вручную. Известная/сохранённая точка входа служит запасным вариантом при пустом ответе SW.

Оригинал второго файла назывался «Свердловка (2).swp». Поддерживаются префиксы «Свердловка», «Сверловка», «Weldment Drilling». Не требуй переименовывать файл: запуск использует реальный путь выбранного `.swp`.

Рабочие макросы предоставлены пользователем и ранее сохранены в игнорируемой `local-macros/`; в новом окружении их наличие нужно проверить. VBA не менять, `.swp` не заменять `.bas`. Не публиковать макросы, CAD-файлы, секреты или внутренние адреса. Без серверов, БД и лишних архитектурных слоёв. Публикацию новых изменений согласовывать в текущем чате; исторические разрешения не являются постоянными.

## Сборка и проверки для разработчика

Из корня репозитория, с .NET SDK 8+ и доступными interop установленного SolidWorks 2025:

```powershell
dotnet build addin/portable/SWToolsHub.Portable.csproj -c Release -p:SolidWorksInteropPath="C:\Program Files\SOLIDWORKS Corp\SOLIDWORKS\api\redist"
dotnet run --project addin/tests/folder/Folder.Checks.csproj
dotnet run --project addin/tests/Catalog.Checks.csproj -- config/macros.demo.json
python installer/build-portable.py
git diff --check
```

При изменении приложения сначала собрать и выполнить относящиеся к изменению проверки, затем пересоздать ZIP и checksum. Не публиковать старый ZIP с новым исходным кодом. Не добавлять `bin/`, `obj/` и рабочие макросы в Git.

В текущем облаке ранее использовались `/workspace/.dotnet/dotnet` и `/workspace/.sw-interop-check`; эти пути не гарантированы в новом окружении. Облачные interop NuGet 32.1.0 относятся к API SolidWorks 2024: это проверка компиляции, а не полная приёмка SW2025.

## Подтверждения и открытые проверки

Пользователь подтвердил запуск первого макроса на Windows в предыдущей Portable-версии. Второй выдавал отсутствие файла, затем были замечания к выбору процедуры. Последние изменения: динамическая папка, два выпадающих списка, системный выбор папки и сокращение кнопок.

Последняя облачная проверка: компиляция Portable без ошибок и предупреждений, 15 проверок сканера/обработки процедур. Отдельно ранее прошли 11 проверок JSON-каталога и браузерные тесты. Это не заменяет Windows-приёмку.

На Windows ещё проверить: новый диалог папки (отмена, адресная строка, DPI), сохранение выбора, добавление/удаление файлов, реальный ответ GetMacroMethods, выбор модуля/процедуры, оба макроса на копиях чертежей, неправильный/закрытый документ, отсутствие файла/SW, повторный запуск и ошибки COM. Не заявлять, что все сценарии работают в SW2025, пока это не подтверждено.

## Сохранённые альтернативы

`frontend/` — React + TypeScript + Vite браузерный деморежим с темами, категориями и избранным; эти возможности ещё не перенесены в Portable. `addin/Addin.cs` — альтернативное дополнение Task Pane/WebView2; `Setup.ps1`, старый EXE и административные скрипты относятся к нему. Они не являются основным продуктом для текущего пользователя. `config/macros.demo.json` не управляет динамическим списком Portable.

После существенных изменений обновляй [docs/HANDOFF.md](docs/HANDOFF.md) фактическими результатами и оставшимися шагами. Документация и сообщения интерфейса — на русском.
