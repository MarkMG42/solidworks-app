## Исправленные причины неверных чисел

- Несуществующий лист больше не читается как пустая ячейка/ноль. При этом настоящий пустой лист сохраняется, его пустая ячейка корректно участвует в арифметике как ноль.
- Ссылки на листы и определённые имена учитываются без регистра. Неверные адреса и циклические имена дают ошибку.
- `MATCH` без третьего аргумента больше не выполняет точный поиск вместо приблизительного. Неподдерживаемые условия COUNTIF, шаблоны поиска и форматы TEXT явно отклоняются.
- Проверяется количество аргументов функций; лишние аргументы не игнорируются.
- Исправлены ROUND на десятичных границах (в том числе 1.005 → 1.01), отрицательный TEXT с форматом 0, знаки CEILING и режим CEILING.MATH.
- Исправлена обработка строк TRUE/FALSE в логике и отличия прямых аргументов SUM/COUNT/MAX/MIN от ссылок на текст/логические ячейки. Пустые ссылки корректно сравниваются с FALSE, нулём и пустой строкой.
- SUMPRODUCT проверяет не только число элементов, но и форму диапазонов. MATCH не принимает двумерную таблицу за одномерный список. Массивы не преобразуются молча в скалярные результаты.
- Переполнение не выводится как Infinity/NaN. Неподдерживаемые варианты вычислений отделены от ошибок Excel: IFERROR не может скрыть отсутствие реализации за числом по умолчанию. Обычное IFERROR(1/0,123) продолжает возвращать 123.
- Ошибочный ввод на любом листе блокирует отображение результатов всей книги и экспорт CSV, включая зависимые листы. Числовой список нельзя обойти через JSON-сеанс.

## Защита импорта и пределы проверки

Если XLSX содержит сохранённый результат формулы, импорт сравнивает его с вычисленным. Допуск: `1e-8 × max(1, |эталон|)` для чисел, точное сравнение строк/логических значений. При расхождении файл отклоняется целиком с адресом ячейки. Устаревшие результаты Excel тоже вызовут отказ: файл нужно пересчитать и сохранить в Excel. Если сохранённых результатов нет, доступны только проверки поддерживаемой структуры и вычислений; независимого численного эталона в таком файле нет.

Тесты подтверждают совпадение на проверенных данных, но не доказывают отсутствие всех ошибок на произвольном XLSX и не являются экспертизой инженерной методики исходных книг. В частности, пользовательским книгам нельзя автоматически назначить требования к единицам, допустимым нагрузкам или нормативам. Поддерживается ограниченный набор функций; неподдерживаемые варианты дают явную ошибку. Для ответственного нового расчёта необходимы независимые контрольные значения и проверка применимости исходной методики.

Команды: `npm --prefix web test`, `npm --prefix web run build`, оба браузерных сценария из `web/README.md`.
